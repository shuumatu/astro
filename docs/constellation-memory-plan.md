# 星座、星图与星名记忆功能实施方案（免登录版）

调研及修订日期：2026-10-23。适用项目：Astro Platform。本文是完整产品与工程计划，不代表所有功能已经实现。本次按用户要求，将完整实施范围调整为免登录学习；账号、云端学习记录和自动跨设备同步不列入本次路线图。

实施进度（2026-10-24）：`/learn/sky` 已扩展至 104 课、18 个阶段，覆盖 88 星座图形与 43 颗目标恒星的定位/回忆练习，支持阶段筛选、课号与名称搜索、IndexedDB 保存、到期复习及 JSON 备份恢复。原有 19 课及存档引用保留。新增 `/learn/chinese` 中国星宫路线，41 课按三垣、四象二十八宿和代表星官排列，独立编号与完成统计，共享本地档案。当前使用静态教学星图和初版间隔阶梯；FSRS、独立认形测验、传统星官全集及离线启动仍属后续范围。具体实现和验证见[学习模块说明](../frontend/src/features/sky-learning/README.md)与[中国星宫课程说明](chinese-sky-learning.md)。

建议首先面向中文、裸眼观星入门用户，依托现有 Web 星图，建立“认识形状 → 对应星名与位置 → 从熟悉目标找到邻区 → 换情境验证 → 跨日复习”的学习闭环。北半球中纬度作为首批内容编排示例，实际可见性始终由用户选定地点、时间计算；其他地区用户可选择对应课程或模拟学习。

## 1. 产品目标与边界

“掌握某颗星/某个星座”至少包含四种能力，不能用一个总正确率替代：

| 能力 | 可观察行为 | 对应练习 |
| --- | --- | --- |
| 认形 | 无名称、少量或无连线时辨认星座/星群 | 看图识别、选出骨架星、补关键连线 |
| 星名回忆 | 指定一颗星后能说出它的名字 | 星点 → 中文名，后续增加英文名/编号 |
| 空间定位 | 给出名字后能在星图里找到目标 | 名称 → 点击星点 |
| 星空导航与迁移 | 能从已知目标找到邻区，在不同朝向和日期仍会辨认 | 星跳路线、变化视野、真实观测任务 |

原始课程内容与记忆状态分离：用户可探索所有内容，系统只为实际学过的技能生成复习。首版不强迫背完 88 星座或每颗暗星。

免登录版采用“公开课程与星图数据 + 浏览器本地学习记录”的结构：进入页面即可学习，不要求姓名、邮箱、手机号或定位授权。每个浏览器配置默认一份学习档案，不建立服务端匿名账号，也不通过设备指纹识别用户。换设备由用户手动导出、导入进度。本功能的答题事件和个人掌握度在本机处理，不设计上传学习记录的接口。

首版默认面向同一浏览器中的一名学习者；多人共用浏览器会共用进度，界面应简短说明。多份本地档案切换可另行评估，不作为首版依赖。浏览器中的“本地档案”只是数据集合，不提供身份认证或访问隔离。

天文学概念必须分开：IAU 星座是有边界的天区；连线是识别辅助，存在不同画法；北斗、夏季大三角等熟悉图形属于星群；中国传统星官与现代 88 星座也不是一一对应。[IAU 星座说明](https://www.iau.org/IAU/IAU/Astronomy-FAQs/Constellations.aspx)、[NASA 星群介绍](https://science.nasa.gov/solar-system/what-are-asterisms/)。

## 2. 调研依据及如何应用

| 依据 | 对本功能的设计启发 | 证据边界 |
| --- | --- | --- |
| Carpenter & Pashler（2007）通过回忆地图中被删除的要素，提高之后的地图重绘表现 | 遮住名称、补充骨架、在空白位置找星，提供即时纠错 | 实验是地图学习、约 30 分钟后的测验，不是对本产品长期观星效果的直接验证 |
| Cepeda 等（2006）分布式练习研究综述 | 跨日重复回忆，随掌握情况调整间隔 | 没有适用于所有人的固定“黄金复习日程” |
| Kornell & Bjork（2008）视觉类别学习实验 | 初学后混合不同星图，安排易混目标对比 | 实验材料是画作类别，应用于星座属于设计推断 |
| Carpenter & Kelly（2012）虚拟空间布局研究 | 练习目标之间的方向关系，并用新视点测验 | 实验发现部分视点迁移收益，但不能替代真实夜空和长期保持验证 |
| Anki FSRS 文档 | 独立维护记忆状态、保留复习日志，以目标保持率平衡负担 | 预测值依赖数据和任务一致性，不等于用户已经掌握真实天空 |

来源：[地图提取练习原论文](https://link.springer.com/content/pdf/10.3758/BF03194092.pdf)、[分布式练习综述](https://pubmed.ncbi.nlm.nih.gov/16719566/)、[视觉类别学习原论文](https://web.williams.edu/Psychology/Faculty/Kornell/Publications/Kornell.Bjork.2008a.pdf)、[Anki FSRS 文档](https://docs.ankiweb.net/manual/deck-options#fsrs)。

视点迁移依据：[Tests enhance retention and transfer of spatial learning](https://link.springer.com/content/pdf/10.3758/s13423-012-0221-2.pdf)。

神话、口诀、故事、图像联想用于建立第一条记忆线索，之后仍通过提取练习验证。允许用户写自己的联想。自创口诀标注“记忆提示”，史实和名称来历必须有来源；不将个人联想包装成传统文化事实。

## 3. 推荐的学习体验

### 3.1 首页只有三个主要入口

- **今日练习**：显示预计时长、到期复习、可选新内容。默认每次约 5–8 分钟，允许随时结束。
- **认识星空**：按路线浏览课程，从熟悉锚点向外扩展；可随时回到完整百科。
- **学习进度**：区分“形状熟悉”“星名待巩固”“定位熟练”“已做观测记录”，显示最近练习与待复习内容，并标注“保存在此浏览器”。

这些时长和内容量是首轮产品参数，应经用户试用调整。不要用连续签到作为主要评价；隔几天回来仍能继续，积压时减少新内容。

首次进入直接显示“开始第一课”，旁边提供“导入已有进度”；可选城市、学习目标与每日时长均可跳过。成功写入本地记录后简短提示保存方式，不在第一次访问时要求安装、通知权限或持久化权限。再次进入优先显示“继续上次学习”和到期复习。

“学习设置”中提供每日时长、内容偏好、导出备份、导入进度、清除学习记录；备份入口始终可找，不占据主要教学画面。用户练到一定量后可在结束页提示一次备份，并允许关闭提示。展示“最近导出时间”，不能把浏览器启动下载等同于确认用户已妥善保存文件。

课程学习、今日复习、自由练习共享相同题目和判分模块：课程负责示范与少量新内容，今日复习按到期队列安排，自由练习允许自选目标。三者均记录提示/答案曝光；有效的独立提取可进入统一调度，同场连续重复或刚看过答案的练习不直接推高长期掌握状态。

### 3.2 一次学习的完整过程

1. **看一个锚点**：先展示 3–7 颗关键星的相对位置与亮度，说明一项最容易辨认的结构特征。
2. **建立名称联系**：一次加入 2–3 个主要名称。将名称与所属星座、在图形中的位置相联系。
3. **撤掉部分提示**：从“星点 + 连线 + 名称”过渡到“星点 + 连线”，再到“星点 + 周围背景”。
4. **双向回忆**：既做“名字 → 找星”，也做“星点 → 回忆名字”；两者分别记录成绩。
5. **即时反馈**：展示所选目标与正确目标，指出一个可用的区别；答错后隔几题再试，避免刚看完答案就算掌握。
6. **换情境验证**：使用另一合理时间/视野的星图，防止只记住屏幕上的坐标。
7. **安排复习**：结束页告诉用户具体薄弱项与下次建议复习时间。

练习可降级为选择题提供帮助，但“有选项答对”和“无提示回忆成功”需分别统计。

自由回忆题申请选项后，按原始无提示任务未成功处理。原本就是选择题的认形任务可独立调度；后续升级到自由输入时，不直接沿用选择题的记忆稳定性。

### 3.3 完整单元样例：夏季大三角

这一单元先学 3 颗星和三角形，再分别扩展到天琴座、天鹰座、天鹅座。夏季大三角由 Vega、Altair、Deneb 构成，可作为较亮的星空锚点。[NASA 星群介绍](https://science.nasa.gov/solar-system/what-are-asterisms/)。中文名映射使用现有经过来源标注的文化数据。

| 物理对象 | 默认中文显示 | 西方专名 | 后续可学 |
| --- | --- | --- | --- |
| HIP:91262 | 织女一（织女星） | Vega | 天琴座、α Lyr |
| HIP:97649 | 河鼓二（牛郎星） | Altair | 天鹰座、α Aql |
| HIP:102098 | 天津四 | Deneb | 天鹅座、α Cyg |

建议顺序：展示三颗星 → 隐藏名称让用户点出织女星 → 标出另一颗星请回忆名称 → 重新给出三颗星让用户辨认星群 → 插入其他题 → 在另一有效星空情境再次寻找。进入后续课程后，再在同一张图里联系三个星座。

联想提示可以使用“织女—天琴、牛郎—天鹰、天津四—天鹅”，解释为课程自编记忆关联。不要硬编码“左上角就是织女星”；屏幕方向会随视角改变。

### 3.4 提示分级

| 级别 | 提示内容 | 成绩处理 |
| --- | --- | --- |
| 无提示 | 题目和必要背景 | 可计入独立回忆 |
| 结构提示 | 如“先找三颗近似排成一直线的腰带星” | 记录辅助程度 |
| 范围提示 | 缩小搜索区域，但不直接标答案 | 记为辅助完成，原始独立提取未成功 |
| 显示答案 | 高亮目标和名称，允许重学 | 不计为无提示答对 |

图形题建议支持“我不知道”和“看提示”；不要强迫用户盲猜。屏幕阅读器、键盘选择与点击交互必须遵循同一提示等级，避免隐藏标签通过可访问性文本提前泄露答案。

## 4. 课程结构与内容范围

正式从零教学顺序见[从零开始记忆星图：完整课程顺序](./sky-memory-curriculum.md)。默认按读图基础、北方定向、冬季、春季、夏季、秋季、四季连通、星名第二遍、邻区补全、南天与全天综合编排；真实观测按当季可见性调整。该文给出完整 88 星座首次学习索引，本文的夏季大三角是单元设计样例，不规定它为所有用户的第一课。

首批课程建议围绕北斗寻北、猎户及冬季亮星、夏季大三角三条路线展开。北斗的识别作为星群教学，随后再扩展到大熊座；不要把两者当作同一个教学对象。

| 阶段 | 内容建议 | 学习目的 |
| --- | --- | --- |
| 试验单元 | 夏季大三角 3 星，或观测条件更适合的猎户单元 | 验证点击、隐藏提示、双向练习与反馈 |
| 首版课程 | 8–12 个常见星座，20–30 颗亮星，3–5 个星群/导航路线 | 形成可持续学习的内容量 |
| 扩展课程 | 更多季节星空、南天内容、易混目标、中国传统星官专题 | 覆盖不同兴趣和观测地区 |
| 进阶专题 | 英文专名、拜耳编号、更多星官与文化比较 | 按用户目标选学 |

数量是范围建议，最终通过数据可用性与可见性审核确定。每单元只引入少量名称，不把一个星座的全部主要星、英文拼写、编号、神话一次性塞进同一课。

课程推荐同时考虑基础知识、到期复习、用户兴趣和当地可见性。明确区分“今晚可看”和“模拟学习”；地平线下的对象仍可以通过指定模拟时间学习，但不能宣称它此刻可见。季节名称只作习惯标签，不作为全年通用的可见性判断。

“今晚可看”还应检查日落后的时段、太阳高度、目标高度和基础亮度条件，并提示这是几何与简化亮度条件下的推荐；天气、遮挡和实际天空亮度会影响观测。用户可直接选择城市，不必提供精确定位。首次进入用少量可跳过的诊断题识别已有基础，允许跳过已熟悉的讲解。

## 5. 练习题型与优先级

| 优先级 | 题型 | 实现方式 | 验证能力 |
| --- | --- | --- | --- |
| P0 | 看名字找星 | 给名称，在星图点击对应物理对象 | 空间定位 |
| P0 | 看星点回忆名字 | 高亮目标，文本输入；可申请选项提示 | 名称提取 |
| P0 | 看局部辨认星座/星群 | 隐藏标题，选名称；后续增加自由输入 | 认形 |
| P0 | 换情境重复上述题 | 替换合理时间/视野并重新计算位置 | 初步迁移 |
| P1 | 选择骨架星、补关键连线 | 按本课采用的连线版本检查关键点/边 | 结构记忆 |
| P1 | 易混对比 | 同屏或交替展示用户经常混淆的两个目标 | 区别学习 |
| P1 | 星跳导航 | 从已知锚点找到下一个目标，逐步减少路径提示 | 邻区关系 |
| P2 | 真实观测任务 | 当地可见目标清单、暗色界面、离线内容与观测记录 | 实景应用 |
| P2 | 语音或自由绘图 | 发音校验、图结构识别需额外设计 | 提升交互多样性 |

连线题按“本课程采用的图形”判定，不声称只有一种官方画法。评价关键星和关键连接关系，允许反向绘制、不同起点，不用鼠标轨迹的像素重合度作为知识成绩。

真实观测记录由用户自行确认，单独展示；它不是自动验证的科学识别成绩。若以后加入照片识别，需建设图像与天文标定能力，作为独立项目评估。

## 6. 记忆模型与调度

### 6.1 最小记忆单元

建议采用 `目标 + 技能 + 必要的语言/文化语义` 作为记忆单元。例如同一颗星至少有“中文名回忆”和“给名定位”两个单元；同一星座的不同文化连线也可能需要独立认形单元。

不要为每张截图、每个旋转角、每个时间创建新卡。情境是练习实例的属性，同一技能在多个情境中复习。任务语义明显不同的题型不要无条件混合其记忆模型。

内容版本与单元身份分离：修改措辞、添加别名不应清空进度；目标或评分语义发生变化时，提供明确的单元迁移规则。题目实例固定内容与算法版本，以便解释历史成绩。

| 数据 | 必要字段 |
| --- | --- |
| LearningUnit | id、targetType、targetId、skill、language、cultureId（适用时）、courseVersion、prerequisites |
| QuestionInstance | id、unitId、templateId、seed、observer/time、viewport、hintPolicy、catalogVersion、contentVersion、可接受答案/评分版本 |
| AttemptEvent | eventId、unitId、questionId、实际回答对象或文本、首次正确性、提示/答案曝光、有效作答时长、reviewedAt、情境、事件序号、最终 rating、schedulerConfigVersion |
| MemoryState | unitId、algorithmVersion、status、dueAt、lastReviewAt、stability、difficulty、reps、lapses |
| Session | id、开始/结束、队列、进行中题目、暂停与恢复状态 |
| LocalArchiveMeta | archiveId、schemaVersion、createdAt、lastExportedAt、课程/星表版本、不可变调度配置版本 |

`archiveId` 只用于识别备份数据集合，在本地创建并随备份携带，不是账号 ID，也不发往服务端。记录不要求 `userId`、登录 token 或服务端设备注册。

UI 显示的“熟练”应有解释，比如“已跨日、无提示答对，并在不同视野成功”。不要用固定百分比暗示真实的个人记忆概率已经测准。早期可采用“初识/巩固/熟练/需复习”的可解释状态。

### 6.2 推荐调度方案

正式 MVP 以可替换的 `ReviewScheduler` 接口接入一个经过验证的 FSRS 实现；先使用默认参数，不急于训练个人参数。目标保持率可从约 0.9 开始试用，后续结合实际负担调节。它是到期复习时的模型目标，并非学习效果保证。[Anki 调度说明](https://docs.ankiweb.net/manual/deck-options#desired-retention)。

快速交互原型若暂时不接调度库，可用可配置的 1、3、7、14、30 天作为演示阶梯；必须明确这是工程占位规则，不是被研究证明适用于所有用户的日程。不要自己拟合一条通用“艾宾浩斯曲线”并显示虚假的精确遗忘百分比。

FSRS 接入注意：`ts-fsrs` 是可选 TypeScript 实现，仓库采用 MIT 许可；本次查询到的 README 标明 v6 要求 Node >=24，而项目当前 engines 声明 >=20。实施时检查实际运行环境、所选版本与浏览器构建兼容性，固定依赖与算法版本，不能直接装 latest 并假设兼容。[ts-fsrs 官方仓库](https://github.com/open-spaced-repetition/ts-fsrs)。

评级建议：忘记、答错或需要内容提示才完成，对无提示技能按失败处理；无提示正确可默认为 Good，允许用户标记费力/轻松。Hard 表示费力但成功回忆，不表示忘记；不要把点击速度直接转换为 Easy。无障碍操作、输入法、后台停留和渲染等待不应被误判为记忆困难。

### 6.3 队列规则

- 优先处理到期内容，再分配有限的新单元；待复习过多时自动降低新增量。
- 学习初期先少量同类引导，之后插入其他星座或易混对象，避免全程固定顺序。
- 正反向题避免紧邻出现；刚刚展示答案的单元标记为已曝光，不能马上作为独立掌握证据。
- 曝光记录覆盖关联目标：展示完整星群答案时，其相关成员的正反向题也受影响。同场仍可继续练习，但这类近期曝光后的成功不作为独立迁移证据。
- 失败后在本次会话稍后或下一次安排重学，避免同题机械重复占满整场。
- “今晚能看到”可提高优先级；非当季内容仍能进行模拟复习，避免长期不复习。
- 新视野难度逐渐增加，记录情境差异；不在一次题目中同时改变所有条件。

### 6.4 免登录环境中的复习与提醒

调度算法在浏览器内执行。每次进入学习首页、开始会话或从后台回到页面时，根据当前时间和本地 `dueAt` 重新计算队列；每次有效作答后保存下次到期时间。关闭页面期间无需后台任务运行，下次打开即可发现已经到期的内容。

时间戳统一保存为 UTC，界面按当前时区显示日期；日学习目标按本地自然日计算，时区变化只改变显示与日统计归组，不重置记忆状态。明显的系统时间回拨保留原始记录并提示核对时间，不用负间隔更新算法。

首版提醒仅在页面内显示，例如“今天有 6 项需要复习”，不承诺关闭浏览器后主动通知。用户设置的每日学习时长用于生成合适队列，不代表创建了后台定时通知。操作系统通知、推送和日历导出不作为本期依赖。

## 7. 星图出题与评分的关键规则

### 7.1 可解性先于随机化

每个题目模板明确必要星点、候选区域、视野范围、亮度限制与最小间距。生成场景后，检查目标和关键骨架是否都存在、位于题目视野内、未被地平线截断、未被面板遮挡、可被输入设备准确选择。失败时换场景，达到上限后使用人工审核的备用场景。

普通点击题通过现有 hit-test 得到物理对象 ID 后评分。扩大手机点击区域时限制相邻目标重叠；多星挤在一起时提供局部放大，不能悄悄偏向正确答案。没有真正点到星的空白点击可提示重试并单独记录，不必立即判断天文知识错误。

练习星群成员时，显式记录核心成员集合；星座区域归属题与连线成员题使用不同语义。图形路径中的恒星列表不能代替整个 IAU 天区里的恒星集合。

### 7.2 变化必须保持天文几何

可变化时间、观察地点、合理视野、整体图表朝向、背景星密度以及显示极限星等。优先通过现有 Worker 重新计算实际星空，不随机移动单颗星、不任意拉伸或镜像星座。

若增加整体图表旋转，地平线方向、标签位置和命中测试都必须同步更新，并明确是图表朝向变化；当前组件不能被假设已经支持这种变换。初版可先使用不同真实时间的预设场景。

调整极限星等只是一种简化显示，不能直接等同于真实光污染等级；降低密度时需确保题目仍可解。颜色可作为辅助，不作为唯一正确线索。

### 7.3 输入答案与别名

基础课允许已审核的常见别名；“织女星”“织女一”可映射同一物理对象。专门考正式名称或拜耳编号时，题目必须提前说明要求，并区分“认对对象”和“名称格式未达本题要求”。

使用显式答案集合和现有名称数据；忽略合理空格、大小写、全半角差异。简繁形式优先使用已存储的明确别名，不进行会产生歧义的任意转换。“参宿四”和“参宿七”不能因编辑距离很近而自动算对；数字与编号差异通常具有天文学意义。同名冲突必须消歧，不允许自动取搜索结果第一项。

### 8.1 第一项必要改造：统一控制提示显示

当前 `SkyMapCanvas.vue` 约第 199–222 行中，特色星群名称会单独绘制，选中星点/特色星群成员也可绕过 `showStarNames=false` 而继续显示名字。`SkyMapView.vue` 的选择流程还会读取别名与详情。因此只关闭星名开关不能形成可靠的测验。

建议引入 `presentationPolicy`/`assessmentPolicy`，由学习会话统一控制：普通名称、选中名称、悬停信息、星群标题、连线、插图、搜索、详情卡、可访问性文本，以及何时可揭示答案。测验里的点击应发送 `answerAttempt`，不要自动触发百科跳转。答题后再进入反馈状态展示内容。

将此策略贯穿显示和交互入口；不把一切职责堆进现有大组件。探索模式保持其正常行为，通过显式配置复用渲染与几何逻辑。

### 8.2 本地学习记录与模块职责

首版使用 IndexedDB 保存课程进度、答题事件、调度状态、个人联想和进行中的会话；Pinia/组件状态只负责当前界面，localStorage 延续用于主题与语言等少量轻量配置。星表和课程是可以重新获取的公开内容，与不可替代的个人记录分别管理。IndexedDB 提供异步结构化存储与事务，适合此处的数据关系。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology)。

建议新增 `LocalLearningRepository` 封装存储，`ReviewScheduler` 纯计算，`SessionController` 管理会话，`BackupService` 负责版本化导入导出。调用链是“题目作答 → 评分 → 调度计算 → 本地事务保存 → 界面反馈”。课程可以随部署发布静态 JSON 或通过现有公开内容接口分发，恒星计算继续使用现有 Worker。

每次提交都保存，不能只在退出页面时保存。调度更新、答题事件和会话检查点写入同一短事务；事务完成后才显示“已保存”。每个事件带唯一 ID；重试提交时不会重复计分。原始事件保留，汇总状态可重建。

调度配置采用不可变版本，保存目标保持率、模型参数与评级映射规则；事件引用当次配置，并保存最终 Again/Hard/Good/Easy 评级及是否进入调度。普通探索、看答案和被取消的题目可以记录曝光，但不应伪造成成功复习。重放时保留用户当时的费力/轻松选择，不从作答时长重新猜测评级。

多标签页首版采用“一次只允许一个有效答题会话”的规则，其他页面可以浏览进度。通过事务校验活动会话及修订号，旧页面的提交不能覆盖新状态；标签页通信仅负责及时刷新提示，不作为唯一的正确性保证。崩溃恢复、导入或重置使旧会话失效。普通界面刷新可继续本机的检查点，已揭晓答案的题不能恢复成未见过答案的测验。

浏览器拒绝存储或写入失败时，不显示保存成功；保留待提交事件供重试。允许用户明确选择“仅本次练习”，其临时记录可导出但不承诺关闭后恢复。不能把无法保存与没有学过混为一谈。

### 8.3 备份、恢复与手动换设备

首版提供版本化 JSON 下载，例如 `astro-learning-2026-10-23.json`。内容包括档案标识、导出时间、数据格式版本、课程/星表引用、完整已提交事件、记忆状态快照、调度配置及学习偏好。个人联想和观测记录如果已经上线，也纳入备份；原始星表、图片、管理员凭证和未提交题目不打包。跨设备恢复从已经提交的进度继续，未完成的题目重新出题。

首版只支持“恢复整份备份”，不提供自动合并两台设备各自的新记录。具体流程：选择文件 → 本地校验格式、大小、版本及引用 → 预览备份时间/已学内容/答题数量 → 提供当前进度导出 → 明确确认替换 → 在事务中完成恢复。验证失败、版本不支持或写入失败时，当前档案保持不变。重复恢复同一个文件不会增加答题次数。

恢复保留原始答题时间和到期时间，不把所有项目重置成今天；旧算法/数据格式使用明确的迁移器，不支持的未来版本应拒绝导入。课程尚未下载的记录仍保留，相关任务暂不可用，不因内容暂缺清空学习历史。

换设备流程为：旧设备导出 → 用户自行传文件 → 新设备导入 → 在新设备继续。若两台设备后来都继续学习，首版需要用户选择保留哪份完整进度，界面不能把导入描述为实时同步。

浏览器存储通常按协议、域名和端口隔离；清除网站数据、部分隐私模式或浏览器回收都可能影响记录。保持正式站点地址稳定，换域名/端口前提示导出迁移；可提供按需申请持久化存储的设置项，但它不能代替外部备份。无法可靠检测所有无痕场景，不设计“已检测到所有可能丢失情况”的提示。[MDN 存储保留与清理规则](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

“清除学习记录”需要单独确认，只删除本学习模块的数据并使当前会话失效，不调用全站 localStorage.clear()，不影响主题、语言和已有管理功能。备份文件中包含个人学习历史，导出时简短说明，文件由用户自行保管。

### 8.4 在线发布与后续离线包

免登录首版仍通过网络加载应用、课程和星表。学习记录本地化不等于页面已经支持断网重开：当前未建设的 Service Worker、资源预缓存和离线版本管理需要单独实施，首版不得直接宣称全面离线可用。

后续离线包缓存完整应用入口及所需脚本、样式、字体、星图 Worker 依赖、课程、星表和所选文化包；公开内容可重新下载，学习档案继续放 IndexedDB。资源完整且校验通过后才显示“可离线学习”，失败时保留上一套完整内容。会话使用固定内容版本，更新在会话结束后生效。删除下载内容不删除进度。

Service Worker 的离线缓存机制需要在支持的安全上下文中部署；正式环境使用 HTTPS。至少验证断网后的冷启动、课程选择、答题保存、到期复习和重新联网更新，不能只测试一个已经打开的页面断网后还在运行。[MDN 离线缓存指南](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching)、[MDN Service Worker 使用指南](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。

### 8.5 内容与许可

天文数据、名称、连线和插图分别维护来源、版本、许可、修改记录。Stellarium 的星空文化可以参考其表现与数据组织，但各内容包和图片的许可需要逐项核对；不因软件开源就认为所有素材可随意复制。[Stellarium Sky Cultures](https://stellarium.org/skycultures.html)、[Stellarium User Guide](https://stellarium.org/guide/)。

首版直接使用项目已有星表、文化数据与图层，避免再接入一套重复引擎。中文优先名、文化连线和界面语言最好分别配置，例如现代星座连线配中文常用星名，但应保留每个名称的文化和来源信息。

这种展示组合已有参考：[Stellarium Chinese Contemporary](https://github.com/Stellarium/stellarium-skycultures/blob/master/chinese_contemporary/description.md)。使用其具体内容前仍按资产逐项核对许可。

## 9. 效果评估与验收

### 9.1 学习效果

主要指标是首次无提示回忆成功率及其延迟保持，分别统计名称回忆、定位、认形和新情境题。建议设置 7 天、30 天回访测验，并注明测验前间隔内是否练习过；不要把刚复习后的成功率当作长期保持率。

试验可比较“相同学习时间的浏览模式”与“提取练习 + 复习模式”，使用事先留出的情境，平衡两组内容难度和初始基础。小规模试用用于发现交互问题，不能凭十几人的结果宣称显著提升。若要量化效果，另行设计样本量与统计方案。

同时跟踪每个正确识别需要的学习时间、提示依赖、混淆对象、复习积压和放弃节点。连胜、积分和打开次数属于参与度，不代替记忆成绩。

免登录阶段的进度和这些指标在本机计算，首页不展示来源不明的全站排名或“全国平均”。正确率同时显示题目数量与时间范围，避免几道题产生误导性百分比。7/30 天测验在用户达到相应时间后再次访问时安排，并记录实际间隔。小规模效果研究通过招募试用、现场观察或用户主动导出诊断摘要完成；没有上传机制时，不能声称后台能够统计全站留存或自动跨浏览器识别同一人。任何后续研究数据提交应单独明确用途与所含字段，不作为正常学习的条件。

### 9.2 工程验收

- 无提示测验中，不会从选中标签、悬停、特色星群标题、搜索、详情或可访问性文本提前看到答案。
- 每题目标在渲染帧与点击命中集合中一致；无不可见、被截断、过暗或无法区分的必答目标。
- 中文别名、英文名、编号、简繁体及同名冲突按规则判定；语义不同的编号不被模糊匹配放行。
- 刷新/崩溃后恢复状态；重试提交不重复更新记忆；跨日、时区变化和多标签页处理正确。
- 同一输入事件与算法版本得到可复现的调度结果；算法升级可迁移或重建。
- 无登录状态下可完成选课、答题、个性化复习、查看进度、备份恢复，学习过程不请求身份服务或上传个人答题事件。
- 同一浏览器关闭后重开可读取已提交进度；不同浏览器/设备的迁移通过明确的手动备份流程完成。
- 损坏备份、未来格式、重复导入和存储中断不会部分覆盖或重复累加；导入后保留真实到期时间。
- 存储失败可重试或进入明确的临时模式；清除学习记录不影响全站其他数据。应用升级有数据迁移路径。
- 后续离线包必须通过断网冷启动验收，首版在线版本的本地存档不替代该验收。
- 手机触控、缩放/平移后的点击命中准确；键盘完成核心任务；颜色并非唯一反馈。
- 为现有天空探索页保留回归检查；扩展训练不破坏原有详情、搜索与显示控制。

测试重点放在上述真实失效模式。复用当前 Vitest、星图投影/Worker 测试基础，增加会话状态机、评分、存储事务和少量端到端关键流程；文案和普通静态课程调整无需机械堆测试。

以上是熟悉仓库的开发者基于现有引擎的初始人日估计，包含核心验证，但不构成交付日期承诺。天文内容审核、完整视觉设计、长期用户试验与浏览器兼容性会影响日历时间；完成阶段 A 后重新估算。各阶段均不包含用户登录或云端学习记录。

最先开始的任务顺序：定义三种核心题目的输入/输出与判分 → 统一提示显示策略 → 制作一个完整学习单元 → 保存原始答题事件和会话检查点 → 验证不同场景下仍可解 → 接本地调度与进度页 → 完成备份恢复与异常处理 → 扩大课程。每一步都能产生可体验、可评估的结果。
